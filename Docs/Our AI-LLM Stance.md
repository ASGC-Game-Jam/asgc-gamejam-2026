# Our AI/LLM Stance 

Here is the stance on AI/LLM-based technologies per department below.

Please contact your [lead](https://discord.com/channels/1511905718419198013/1519147749902123238/1519147749902123238) if you have any questions, comments, or concerns. Thank you!

### Tech
* Use for code generation: Yes, but disclose
* Use for tool generation: Yes
* Use for debugging/refine: Yes, must be able to explain work

### QA
* AI assistance is okay for helping write test cases, completing repetitive work, and building automation
* AI use should be disclosed and human-reviewed for quality
* AI should not be used to build something in its entirety. The point of doing the work is to understand what is actually being built, how it works, and why it is the way it is
* AI is not okay for subjective testing, like Usability Testing. That is the human part of quality, where real people’s thoughts, opinions, and experiences matter the most

### Tech Design
* Use for content generation: No
* Use for tool generation: Yes, disclose use
* Use for debugging/refine: Yes, for spell check

### UI/UX Design
* Use for code generation: No
* Use for tool generation: No
* Use for debugging/refine: No

### Art
* Content creation: No final artwork can be AI. All art must be made by the artist
* Tool creation: Limited AI use permitted for tool creation, scripting, and technical artwork
* Support work: AI use for annotating messages and summaries is allowed

### Production
* AI is okay as a tool for note-taking and summarization of text. Production will not be creating code or debugging

### Audio
* AI assistance for Docs is okay
* AI for content: No
* AI is okay for tech assistance. Using it to learn or assist with blueprints/MetaSounds, etc. is okay. Human review

### Narrative
* Use for content generation: No
* Use for tool generation: No, unless a specific disclosed use case is discussed and approved by leads
* Use for debugging/refine: No, we will have editors specifically developing refinement skills
