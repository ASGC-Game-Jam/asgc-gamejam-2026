# Journal Objectives

Issue #144 adds a read-only Objectives view. `UAtlantisJournalObjectivesWidget` is embedded by the Journal shell and refreshes on `OnObjectivesChanged`. It shows the supplied objective state and text, then optional context and location. It has no completion controls, clue inspection, rewards, markers, or puzzle solution generation.

## Ownership and integration

Objective State & Progression (#190, currently open) owns objective state. No implementation of that owner or authored Beta objectives exists in the current source/Blueprint exports. Until that dependency lands, the Blueprint-callable `UAtlantisJournalObjectivesSubsystem::SubmitObjectiveSnapshot` is the explicit presentation adapter. The owner must submit its full ordered snapshot of **disclosed player-facing objectives** after initial load and whenever state, text, context, or location changes. Do not submit hidden objective data or internal solution text; presentation cannot infer which authored text is safe to disclose.

The adapter validates nonempty IDs, unique IDs, nonblank objective text, and supported states before replacing anything. It returns false on invalid input and retains the previous snapshot. An empty snapshot removes all entries. Stable IDs identify records; owner order determines display order. Snapshot getters return copies. There is no state transition API or gameplay persistence here.

Completed and failed objectives are hidden by default. Design can call `SetHistoryVisibility` to expose either independently. The snapshot keeps these records so toggling presentation policy loses no data. These defaults are a reversible conservative first-pass policy pending Design approval. Location is displayed only when explicitly provided by the owner; the Journal adds no precision, coordinates, or map markers.

The subsystem follows the existing `UAtlantisJournalSubsystem::OnJournalCleared` event for run/menu reset. On load the objective owner should republish its current disclosed snapshot, avoiding a competing quest save state. Closing/reopening the widget retains presentation data; NativeConstruct subscribes and renders the current snapshot, and NativeDestruct unsubscribes.

## Existing implementation

The existing `WBP_Journal` handles Investigation, Puzzle, and Dialogue tabs, next-tab navigation and notification blinking. `UAtlantisJournalShellExtensionSubsystem` discovers the actual existing shell instance in its game world every 0.25 seconds and attaches one native `UUserWidgetExtension`. The extension adds an Objectives button beside the existing tab buttons and a native view alongside the current content. It leaves the controller's Journal input and pause handling in place and modifies no binary assets or exported graphs. Discovery releases its ticker during subsystem shutdown; the widget extension releases button delegates and inserted children when the shell destructs. The existing Blueprint closes its Journal by changing visibility, so extension children remain available between ordinary close/open actions.

The extension validates the expected named widgets and supported parent layouts before attaching. The existing PR #283 layout uses `TabGridPanel` (GridPanel) for its tab buttons and `VerticalBox_67` for content. Objectives joins a fourth grid column, copying the existing button slot alignment and style. Its content sibling copies the existing VerticalBox slot size, padding and alignment. HorizontalBox tab rows and CanvasPanel/Overlay content are also supported. Unsupported authored layouts fail with a diagnostic instead of being restructured. `Atlantis.Journal.ExistingShellLayout` prints widget names, parents, slots and tab properties from the real loaded asset so layout compatibility can be checked.

The current Blueprint enum maps Investigation/Puzzle/Dialogue to 0/1/2 and has an unused fourth branch. Objectives uses that fourth value while selected. Clicking an existing button or the Blueprint next-tab action exits Objectives through the existing state update; extension destruction restores the preceding selection. Ordinary visibility-based close/open retains the selected section. The optional #142 native view is discovered by class path and filtered through its `SetKnowledgeFilter` API for the Investigation/Puzzle tabs. `CreateWidget<UAtlantisJournalObjectivesWidget>` remains available for a future authored Objectives tab.

## Validation

Automation test `Atlantis.Journal.ObjectivesSnapshot` covers supplied state and text, optional fields, independent completed/failed visibility, stable order, mutation isolation, atomic rejection, removed entries, and run reset. `Atlantis.Journal.ObjectivesViewUpdates` covers already-open widget refresh and legacy reset. `Atlantis.Journal.ExistingShellExtension` uses the real Journal Blueprint and Atlantis player controller to exercise all existing tab buttons, embedded updates, reflected tab changes, cleanup and reconstruction. Build `ProjectAtlantisEditor` Development Editor / Win64, then run `Atlantis.Journal` tests in the Unreal Session Frontend or via `UnrealEditor-Cmd -ExecCmds="Automation RunTests Atlantis.Journal;Quit" -unattended -NullRHI`.

For PIE: open the Journal and select Objectives; submit an active snapshot through the owner adapter; confirm updates while open, completion/failure visibility under each policy, blank optional-field omission, and a long scrollable localized description. Close/reopen and confirm the latest snapshot, then invoke legacy Journal `ClearAll` and confirm no old entries remain. Check the existing Investigation, Puzzle and Dialogue controls still work. Real Beta objective validation remains blocked by #190 and authored objective data; synthetic examples are not a substitute.
